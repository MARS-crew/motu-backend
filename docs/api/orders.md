# 주문

[← API 명세서 목차](README.md)

매수·매도 주문, 주문 취소, 내 주문 조회, 호가. [호가 5단계](#호가-5단계)는 **로그인 불필요**이고, 나머지는 모두 **로그인 필요**입니다.

## 거래 규칙

| 항목 | 규칙 |
|------|------|
| 주문 종류 | 지정가만 있습니다. (시장가 없음) |
| 거래 시간 | 24시간. 장 마감, 자동 취소, 가격 제한폭이 없습니다. |
| 거래 상대 | 다른 회원의 주문과 체결됩니다. |
| 체결 순서 | 가격이 좋은 주문이 먼저(매수는 높은 가격, 매도는 낮은 가격), 같은 가격이면 먼저 들어온 주문이 먼저 체결됩니다. |
| 체결 가격 | 호가창에 **먼저 있던 주문의 가격**입니다. 매수 5,000P 주문이 호가창의 매도 4,900P 주문과 만나면 4,900P에 체결됩니다. |
| 부분 체결 | 상대 수량이 모자라면 체결된 만큼만 체결되고, 남은 수량은 호가창에 남습니다. |
| 정정 | 없습니다. 취소 후 다시 주문합니다. |
| 거래 상태 | `ACTIVE` 상품만 주문할 수 있습니다. `PAUSED`(거래 중지)이면 걸린 주문은 그대로 남고 새 주문만 막히며, 취소는 됩니다. `CLOSED`(거래 종료)가 되면 미체결 주문이 모두 자동 취소됩니다. |
| 상장 직후 | 상장 신청자의 발행 주식 전량이 상장가에 매도 주문으로 걸린 상태로 거래가 시작됩니다. |
| 수수료 | 체결 금액의 **0.02%**, 원 단위 미만 버림. 매수·매도 모두 냅니다. (예: 67,000P 체결 → 13P) |
| 체결 알림 | 체결될 때마다 매수자·매도자 모두에게 [알림](notifications.md)(`type: "ORDER"`)이 쌓입니다. 부분 체결이면 체결된 건마다 하나씩입니다. |

### 상품별 주문 규칙

상품마다 다르며 [주문 가능 정보](#주문-가능-정보)로 받습니다.

| 항목 | 규칙 |
|------|------|
| 호가 단위 `priceTickSize` | 주문 가격은 호가 단위의 배수여야 합니다. |
| 최소 주문 가격 `minOrderPrice` | 이보다 낮은 가격으로 주문할 수 없습니다. |
| 최소 주문 수량 `minOrderQty` | 이보다 적은 수량으로 주문할 수 없습니다. |

### 포인트와 수량 예약

| 주문 | 주문할 때 | 체결될 때 | 취소할 때 |
|------|------|------|------|
| 매수 | `주문 가격 × 수량 + 수수료`만큼 포인트를 예약합니다. 예약된 포인트는 다른 주문에 쓸 수 없습니다. | 체결 금액과 수수료를 보유 포인트에서 빼고, 체결된 만큼 예약을 풉니다. 주문 가격보다 싸게 체결되면 차액은 바로 사용 가능 포인트로 돌아옵니다. | 남은 예약 포인트를 모두 풉니다. |
| 매도 | 주문 수량만큼 보유 수량을 예약합니다. 예약된 수량은 다른 매도 주문에 쓸 수 없습니다. | 체결 금액에서 수수료를 뺀 포인트를 받고, 보유 수량이 줄어듭니다. | 남은 예약 수량을 모두 풉니다. |

- 사용 가능 포인트 = 보유 포인트 - 예약 포인트 ([내 계좌](accounts.md#내-계좌-자산관리)의 `availableCash`)
- 매도 가능 수량 = 보유 수량 - 예약 수량
- 보유 수량이 0이 되면 보유 종목에서 빠집니다.

### 자기 체결 방지

내 미체결 주문과 체결될 수 있는 가격의 주문은 받지 않습니다. (409 `ORDER_SELF_TRADE`)

- 매수 가격이 내 미체결 매도 주문의 가격 이상이거나, 매도 가격이 내 미체결 매수 주문의 가격 이하인 경우입니다.
- 다른 회원의 주문만으로 다 체결되는 수량이어도 거부합니다.
- 기존 주문을 취소한 뒤 다시 주문하도록 안내해 주세요.

### 한 번에 체결할 수 있는 주문 수

주문 하나가 호가창 주문을 최대 100건까지 체결할 수 있습니다. 넘으면 주문을 받지 않습니다. (409 `ORDER_TOO_MANY_FILLS` + `details { maxFills }`)

- 예: 매도 호가에 1주짜리 주문이 150건 걸려 있을 때 150주를 매수하면 거부됩니다.
- 수량을 나눠 주문하도록 안내해 주세요.

## 주문 가능 정보

주문 화면에 들어갈 때 호출합니다.

| 항목 | 내용 |
|------|------|
| API | `GET /api/orders/available?stockId=` |

| 응답 필드 | 설명 |
|------|------|
| `stockId`, `tradeStatus` | 상품 ID, 거래 상태 (`ACTIVE`가 아니면 주문 버튼 비활성화) |
| `priceTickSize`, `minOrderPrice`, `minOrderQty` | [상품별 주문 규칙](#상품별-주문-규칙) |
| `feeRate` | 수수료율 (`0.0002` = 0.02%) |
| `availableCash` | 사용 가능 포인트 |
| `sellableQty` | 매도 가능 수량 (보유하지 않으면 0) |

| 에러 | 상황 |
|------|------|
| 404 `STOCK_NOT_FOUND` | 없거나 삭제된 상품 |
| 404 `ACCOUNT_NOT_FOUND` | 계좌가 없음 (회원가입 때 만들어지므로 보통 생기지 않음) |

- 주문 화면의 예상 수수료 = `가격 × 수량 × feeRate`(원 단위 미만 버림), 매수 총 주문 금액 = 주문 금액 + 예상 수수료, 매도 총 수령 금액 = 주문 금액 - 예상 수수료입니다.
- 매수 "최대 수량"은 `availableCash ÷ (가격 × (1 + feeRate))`의 정수 부분입니다.

## 주문하기

| 항목 | 내용 |
|------|------|
| API | `POST /api/orders` |

| 요청 필드 | 설명 |
|------|------|
| `clientOrderId` | 중복 요청 방지 키 (UUID). [아래](#중복-요청-방지) 참고 |
| `stockId` | 상품 ID |
| `side` | `BUY` 매수 / `SELL` 매도 |
| `price` | 주문 가격 (P, 1 이상 정수) |
| `qty` | 주문 수량 (1 이상 정수) |

응답은 201이고 [주문 항목](#주문-항목)입니다. **주문을 받자마자 체결까지 처리**하므로, 바로 체결되면 응답의 `status`가 `PARTIAL` 또는 `FILLED`입니다.

| 에러 | 상황 | 화면 처리 |
|------|------|------|
| 400 `BAD_REQUEST` | 형식 오류 (UUID 아님, 0 이하, 정수 아님) | `details`의 문구 표시 |
| 400 `ORDER_INVALID_PRICE_TICK` + `details { priceTickSize }` | 가격이 호가 단위의 배수가 아님 | "호가 단위(n P)에 맞게 입력해 주세요." |
| 400 `ORDER_PRICE_TOO_LOW` + `details { minOrderPrice }` | 최소 주문 가격 미만 | |
| 400 `ORDER_QTY_TOO_LOW` + `details { minOrderQty }` | 최소 주문 수량 미만 | |
| 400 `ORDER_INSUFFICIENT_CASH` + `details { availableCash, requiredAmount }` | 매수: 사용 가능 포인트 부족 | |
| 400 `ORDER_INSUFFICIENT_QTY` + `details { sellableQty }` | 매도: 매도 가능 수량 부족 | |
| 404 `STOCK_NOT_FOUND` | 없거나 삭제된 상품 | |
| 404 `ACCOUNT_NOT_FOUND` | 계좌가 없음 (보통 생기지 않음) | |
| 409 `ORDER_STOCK_NOT_TRADABLE` + `details { tradeStatus }` | 거래 가능 상태가 아님 | 주문 버튼 비활성화 |
| 409 `ORDER_SELF_TRADE` | [자기 체결](#자기-체결-방지) | 기존 주문 취소 안내 |
| 409 `ORDER_TOO_MANY_FILLS` + `details { maxFills }` | [체결할 주문 수 초과](#한-번에-체결할-수-있는-주문-수) | 수량을 나눠 주문 안내 |
| 409 `ORDER_CLIENT_ID_REUSED` | 같은 `clientOrderId`로 내용이 다른 주문 | 새 `clientOrderId`로 다시 요청 |

### 중복 요청 방지

- 프론트가 주문 한 건마다 UUID를 새로 만들어 `clientOrderId`로 보냅니다. (`crypto.randomUUID()`)
- 응답을 못 받아 **다시 보낼 때는 같은 `clientOrderId`** 를 씁니다. 이미 접수된 주문이면 새로 만들지 않고 그 주문을 현재 상태 그대로 돌려줍니다(201). 그사이 거래가 중지됐어도 마찬가지입니다.
- 주문이 끝나 다음 주문을 할 때는 새 UUID를 만듭니다.
- 같은 `clientOrderId`인데 상품·방향·가격·수량 중 하나라도 다르면 409 `ORDER_CLIENT_ID_REUSED`입니다.

## 주문 취소

미체결 수량을 취소합니다. 일부 체결된 주문은 남은 수량만 취소되고, 체결된 부분은 그대로입니다.

| 항목 | 내용 |
|------|------|
| API | `POST /api/orders/:orderId/cancel` |
| 응답 | [주문 항목](#주문-항목) (`status: CANCELED`, `remainingQty: 0`) |

| 에러 | 상황 | 화면 처리 |
|------|------|------|
| 400 `BAD_REQUEST` | `orderId`가 숫자가 아님 | |
| 404 `ORDER_NOT_FOUND` | 없거나 다른 회원의 주문 | |
| 409 `ORDER_NOT_CANCELABLE` | 이미 전부 체결됨 | 목록 다시 조회 |

- 이미 취소된 주문을 다시 취소하면 에러 없이 그 주문을 그대로 돌려줍니다. (중복 클릭, 재전송)
- 취소와 체결이 동시에 일어나면 먼저 처리된 쪽만 반영됩니다. 취소 직전에 체결된 수량은 취소되지 않습니다.

## 주문 항목

주문하기·주문 취소 응답, 목록·상세의 공통 필드입니다.

## 호가 5단계

| 항목 | 내용 |
|------|------|
| API | `GET /api/orders/book?stockId=` |
| 로그인 | 불필요 |

| 응답 필드 | 설명 |
|------|------|
| `stockId` | 상품 ID |
| `asks[] { price, qty }` | 매도 호가. 낮은 가격부터 최대 5개 |
| `bids[] { price, qty }` | 매수 호가. 높은 가격부터 최대 5개 |

| 에러 | 상황 |
|------|------|
| 404 `STOCK_NOT_FOUND` | 없거나 삭제된 상품 |

- `qty`는 그 가격에 걸린 미체결 수량의 합계입니다. 주문이 없는 가격은 나오지 않습니다.
- 화면에서 매도 호가를 위에 높은 가격부터 그리려면 `asks`를 뒤집어서 쓰면 됩니다.
- Swagger에는 자물쇠가 표시되지 않고, 토큰 없이 호출합니다.
- 실시간 갱신은 [실시간 시세](charts.md#실시간-시세-sse)의 `orderbook` 이벤트로 받습니다.
